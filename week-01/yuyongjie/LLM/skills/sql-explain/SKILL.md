# SQL 解读 Skill

## 步骤

1. 拆解 SQL：先判断语句类型（SELECT / UPDATE / DELETE / JOIN 子查询 / CTE / 窗口函数）。
2. 用「人话」复述它在做什么，一句话讲清业务含义，再逐段解释：
   - `FROM` / `JOIN`：涉及哪些表，连接条件是什么，谁是驱动表。
   - `WHERE`：过滤条件，**注意是否能命中索引**（对字段做函数运算、隐式类型转换、`LIKE '%x'` 前导通配都会让索引失效）。
   - `GROUP BY` / `ORDER BY`：是否会触发排序或临时表。
   - `LIMIT`：是否在聚合之后才限制（可能白算）。
3. 指出性能风险，按影响排序，每条给出「判断依据 + 建议索引或改写方式」。

## 输出格式（严格遵守）

```
【一句话】…
【逐段解读】
  1. …
  2. …
【性能风险】
  - [高] … 依据：… 建议：…
  - [中] …
【改写建议】（仅在确有收益时给）
```

## 禁止

- 不要假装知道真实执行计划——没有 `EXPLAIN` 数据时只能给「基于语法的推断」，并明确标注这一点。
- 不要输出与性能无关的教科书式科普。

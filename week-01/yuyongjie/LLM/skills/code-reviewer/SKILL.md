# Python 代码审查 Skill

## 步骤

1. 先确认要审查的代码。用户已给出代码就直接用；只给了文件名时，用 `read_file` 读取。
2. 按下面四个维度逐条检查，**每个问题必须给出文件/行号所在的上下文片段**：

   - **正确性**：边界条件、异常路径、资源未释放、可变默认参数、`except` 吞异常。
   - **健壮性**：网络/IO 失败是否有处理、超时是否设置、重试是否有上限。
   - **安全**：密钥硬编码、路径穿越（`..`）、`eval`/`exec`、命令注入、日志泄漏敏感信息。
   - **可维护性**：函数过长、魔法数字、重复代码、命名与注释不一致。

3. 每个问题标注严重级别：`P0 阻断`（会挂/会泄露数据）、`P1 建议`（易出错）、`P2 风格`。
4. **只报能落到具体代码行的问题**，不要泛泛而谈“建议加注释”。

## 输出格式（严格遵守）

先给一句话总评，然后输出 JSON 数组，最后给修复优先级：

```json
[
  {"level": "P0", "where": "llm.py:120", "issue": "…", "fix": "…"},
  {"level": "P1", "where": "tools.py:88", "issue": "…", "fix": "…"}
]
```

## 禁止

- 不要重写整段代码，只给最小修复建议。
- 没有问题就明确说「未发现 P0/P1 问题」，不要为凑数编造。

## 1. 项目概述

### 1.1 做了什么

从「手写一个 HTTP 请求调用大模型」开始，逐步搭建到「带工具调用、Skill、MCP 的
小 agent」，并在此之上做了一个任务数据层（校验 / 分类 / 清单渲染 / 提醒计算）。

全程**不使用 OpenAI / Anthropic 官方 SDK**，直接实现 OpenAI 兼容协议，
把流式分帧、`tool_calls` 增量拼装、重试策略这些细节摊开在代码里。

### 1.2 为什么不用 SDK

- **收益**：请求体、SSE 分帧、工具调用拼装、重试逻辑全部可见可改；
  换厂商只需改 `LLM_BASE_URL` 和 `LLM_MODEL` 两个配置。
- **代价**：图片输入、结构化输出、内置重试策略等高级特性需要自己补。
  生产项目仍建议使用官方 SDK，本项目定位是学习与验证。

### 1.3 交付范围

| 能力 | 状态 | 入口 |
|---|---|---|
| 环境搭建与自检 | ✅ | `cli/env_report.py` |
| LLM API 调通（流式 / 非流式） | ✅ | `cli/chat.py` |
| 工具调用（Function Calling） | ✅ | `cli/demo.py --only 2` |
| Skill 机制（渐进式披露） | ✅ | `cli/demo.py --only 3` |
| MCP 客户端（官方 filesystem server） | ✅ | `cli/demo.py --only 4` |
| 任务数据层（校验 / 清单 / 提醒） | ✅ | `cli/checklist.py` |
| 链路自检 | ✅ | `cli/selftest.py` |
| 平台接入（飞书推送） | ⬜ 未开始 | 见第 11 节 |

## 6. 核心设计

### 6.1 手写 OpenAI 兼容协议

`llm.py` 只发一个 `POST /chat/completions`，处理三种情况：

1. **流式（SSE）**：按行读 `data: {...}`，`[DONE]` 结束；
2. **`tool_calls` 增量**：`id` / `name` / `arguments` 会分片到达，按 `index` 分别累加；
3. **重试**：429 / 5xx / 网络异常指数退避（最多 3 次），401 / 402 / 400 直接失败并翻译成人话。

```python
# 典型调用
response = client.chat(messages, tools=tools, stream=True, on_delta=print)
response["content"]        # 文本
response["tool_calls"]     # [{"id", "name", "arguments"}]
response["usage"]          # token 用量
```

### 6.2 三类能力统一成 Function Calling

本地 Python 函数、Skill、MCP 工具，最终都转成同一种 schema：

```json
{"type": "function", "function": {"name": "...", "description": "...", "parameters": {...}}}
```

所以 `agent.py` 的循环完全不关心工具来自哪里，只关心「模型要不要求调用」。

### 6.3 Skill 的渐进式披露

`skills/<name>/SKILL.md` 的 frontmatter 只有 name 和 description，正文不会被预加载：

- system prompt 里只放「名字 + 一句话描述」的目录；
- 模型判断需要时调 `load_skill(name)`，正文才进上下文；
- 正文里可以写强制输出格式（如 JSON schema），让输出可被程序消费。

### 6.4 数据与展示分离（任务层）

`taskdata.py` 不接任何平台，只做「数据说清楚」：校验、分类、渲染、提醒计算。
将来接飞书时，只需增加「转成飞书卡片 + 调用发送接口」一层，其余不动。

**两个关键实现细节：**

- **逾期按时刻算，不按日期**：17:00 到期的任务，18:00 就该进「逾期」；
- **「现在」从参数注入**（`--at`）：否则「逾期 2 天」这类结论无法复现、无法测试。

## 7. 任务数据格式

文件：`data/tasks.json`

```json
{
  "owner": "我",
  "synced_at": "2026-11-08 18:30:00",
  "tasks": [
    {
      "id": "T3",
      "title": "补 401 与超时的错误路径验证",
      "priority": "P0",
      "status": "doing",
      "due": "2026-11-10 22:00",
      "start": "2026-11-09 09:00",
      "estimate_hours": 1,
      "source": "第一周作业",
      "note": "错误 Key 与断网各跑一次",
      "done_at": null
    }
  ]
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `id` | ✓ | 项目内唯一，重复会被拦下 |
| `title` | ✓ | 非空 |
| `due` | ✓ | `YYYY-MM-DD` 或 `YYYY-MM-DD HH:MM` |
| `priority` | | `P0` / `P1` / `P2`，默认 `P2` |
| `status` | | `todo` / `doing` / `done`，默认 `todo` |
| `start` | | 可选，不能晚于 `due` |
| `estimate_hours` | | 可选，超出 0~8 只警告不拦截 |
| `source` / `note` / `link` | | 自由文本 |
| `done_at` | | 状态为 `done` 时建议填写 |

校验器会把错误定位到 `tasks[n]（id）` 级别，例如：

```
✗ tasks[2] 的 id「T1」与 tasks[1] 重复
✗ tasks[4]（T3）无法解析的日期：'11/13/2026'
✗ tasks[7]（T6）的 start 晚于 due
```

## 8. 使用手册

### 8.1 问答

```powershell
.\run.ps1 chat.py "用一句话解释什么是 MCP"
.\run.ps1 chat.py "你好" --no-stream          # 非流式
.\run.ps1 chat.py "你好" --model deepseek-reasoner
```

### 8.2 四能力演示

```powershell
.\run.ps1 demo.py                 # 全部四个场景
.\run.ps1 demo.py --only 2        # 只看工具调用
.\run.ps1 demo.py --mock          # 无 key 时离线验证
```

| 场景 | 内容 |
|---|---|
| 1 | 基础对话，流式 + 用量统计 |
| 2 | 模型自主调用 `get_current_time` + `calculator` |
| 3 | `load_skill` → `read_file` → 按 Skill 格式输出审查报告 |
| 4 | 通过 MCP 调用官方 filesystem server |

### 8.3 任务数据

```powershell
.\run.ps1 checklist.py                                # 渲染清单
.\run.ps1 checklist.py --today                        # 今天要做什么（含逾期）
.\run.ps1 checklist.py --reminders                    # 未来 7 天提醒计划
.\run.ps1 checklist.py --check                        # 只校验数据
.\run.ps1 checklist.py --at "2026-11-10 08:00"        # 固定“现在”复现判定
.\run.ps1 checklist.py --file data/tasks_dirty.json --check
.\run.ps1 checklist.py --ask "我今天该先做哪件事"
```

**提醒规则**：截止前 1 天 09:00 提醒一次，截止当天 09:00 再提醒一次；
已过去的时间点直接跳过，不补发。

### 8.4 环境与自检

```powershell
.\run.ps1 env_report.py --no-tree     # 环境报告（key 只显示掩码）
.\run.ps1 selftest.py                 # 8 项离线检查，约 3 秒
.\run.ps1 selftest.py --online        # 额外做一次真实调用
```

## 9. 调试方法

### 9.1 优先跑自检

`selftest.py` 把链路拆成独立检查点，各自捕获异常、各自报告：

| 检查点 | 覆盖内容 |
|---|---|
| 运行环境 | Python 版本、是否在 venv 内 |
| 依赖 httpx | 版本可用 |
| 配置 .env | key 是否就绪（掩码显示） |
| 本地工具 | 计算结果、时间、路径穿越防护、未知工具报错 |
| Skill 加载 | 扫描、正文注入、目录进 system prompt |
| 工具 Schema | 每个工具的 name/description/parameters 结构 |
| 任务数据 | 样例数据零错误、分类可复现、脏数据必须报错 |
| MCP 握手 | 连接 server、发现工具、真实调用一次 |
| 真实模型调用（`--online`） | key 与网络可用 |

失败的那一项就是问题所在，不需要逐层猜。

### 9.2 复现时间相关逻辑

所有涉及「现在」的判断都支持 `--at`，例如验证「截止前 1 天提醒」是否正确：

```powershell
.\run.ps1 checklist.py --reminders --at "2026-11-10 08:00"
```

### 9.3 离线验证模型协议

`mock_llm.py` 实现了同样的 SSE 协议，并故意把 `tool_calls` 拆成 4 片下发，
用来验证拼装逻辑。`demo.py --mock` 走的是和真模型完全相同的代码路径。

## 13. 维护须知

### 13.1 加一个工具

```python
# src/your_module.py
from tools import tool

@tool(
    name="my_tool",
    description="给模型看的说明，决定它什么时候调用",
    parameters={"type": "object", "properties": {...}, "required": [...]},
)
def my_tool(...):
    return "结果字符串"
```

前提是该模块在进程里被 import 过（`cli/` 入口或 `selftest.py` 里引用即可）。

### 13.2 加一个 Skill

```
skills/my-skill/SKILL.md
---
name: my-skill
description: 一句话说明什么时候用它
---
正文：步骤、输出格式、禁止事项
```

不需要改代码，`skills.py` 启动时自动扫描。

### 13.3 加一个命令

在 `cli/` 新建脚本，第一行：

```python
import _bootstrap          # 把 src/ 加入 sys.path
```

### 13.4 三条分层规则

1. `src/` 不出现 `argparse` / `sys.exit()` / 菜单打印——那是 `cli/` 的事；
2. 路径只从 `paths.py` 取，不要在别处算 `__file__`；
3. `cli/` 新脚本必须 `import _bootstrap`。

### 13.5 安全事项

- `.env` 存真实密钥，已在 `.gitignore` 中，**不要提交、不要截图**；
- 所有日志与报告中的 key 一律掩码（`llm.redact()`）；
- 文件类工具限制在工作区内，MCP 只挂只读工具；
- 建议在平台侧给 key 设置消费限额。
